# Day 7 — сценарий видео (5–8 минут)

## 1. Задача и почему она продуктовая (0:00–1:00)

- Тезис: «Хочу писать боту "напоминай полить цветы каждый вторник" —
  а сейчас бот понимает только флаги `--weekly 2`».
- Показать `challenge/src/core/todoParser.ts` (флаги) и MCP `add_todo`
  (day-18-server) — куда ляжет тюненая модель (NL → tool-args).
- Схема задачи одним кадром: input → 4 поля JSON; что считается
  верным ответом (точное совпадение); boundary-пунты.

## 2. Датасет: откуда данные и как чистили (1:00–2:30)

- Реальных логов нет → сиды руками (412 шаблонных вызовов, gold по
  построению) + LLM-генерация входов локально (qwen2.5:7b-instruct).
- Кадр: терминал с прогоном `generate_data.py` — счётчики accepted/
  rejected/dup и финальные 463/63.
- Кадр: `data/rejected.jsonl` — 3–4 примера брака: «каждый день» + null,
  «полчаса» → interval_hours:30, висячий «про …» в text. Тезис: rule-
  валидатор отбраковал 27%, а 3 дыры нашёл только ручной просмотр.
- `check_split.py` — OK: утечек eval в train нет, баланс классов
  (weekly 177 / daily 122 / none 116 / hourly 111).

## 3. Замеры без тюна — что должен превзойти тюн (2:30–4:00)

- Кадр: `eval_baseline.py --modes none,prompt` на qwen2.5:1.5b-instruct.
- Показать живые ответы в `baseline_results.jsonl`:
  - none: модель просто болтает, JSON не выдаёт (parse_ok 0/30);
  - prompt: JSON есть (30/30), но «каждый день делай уборку» → daily?
    нет — ошибки в recurring (19/30) и text-чистке (19/30); full_match
    14/30.
- Тезис: промпт фиксирует формат, но не семантику — планка 14/30.

## 4. Обучение (4:00–5:00)

- Конфиг одним кадром: QLoRA NF4 r=16 α=32, fp16, eff. batch 16,
  4 эпохи, early stopping; loss только на assistant-токенах.
- Кадр: MASK CHECK из train_qlora.py — граница маски перед JSON.
- Runbook Kaggle на экране (README): pip → train → evaluate_tuned;
  run.json — что фиксируется (sha256 датасета, GPU, версии, loss).
- Если прогон уже сделан: loss-кривая + числа из tuned_report.md
  вместо заглушки статуса.

## 5. Сравнение и вывод (5:00–6:30)

- tuned vs base-prompt vs base-none на одних 30 кейсах (одна загрузка,
  адаптер вкл/выкл): таблица tuned_report.md.
- Порог успеха дня: full_match ≥ 21/30 при parse_ok 30/30.
- Что изменилось / что осталось: пунт-класс (11 кейсов) — самая
  хрупкая часть.
- Финальный тезис: «данные — 80% успеха: 27% брака отловлено правилами,
  остальное — глазами; формат датасета единый, поэтому модель учится
  и форматированию».
