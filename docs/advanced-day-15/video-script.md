# Day 15 — атака на детерминированную логику партнёра — ПОЛНЫЙ ТЕКСТ ДЛЯ ЗАЧИТКИ

> Этот сценарий — для **детерминированного** прогона (LLM заменена заглушкой).
> Живой прогон с локальной моделью, одной командой и фактическими
> результатами — в `runbook.md`.

Хронометраж: ≈ 9 минут. Фрагментов: 10.

Текст ниже читается **дословно**, фрагмент за фрагментом. Строки
«Экран» вслух не зачитываются — это указания, что показывать и куда вести
курсором. Числа в кадре проговариваются словами, идентификаторы
(`A05`, `P-OUT-09`, `sk-%70roj`) — как есть.

## Как записывать (заглушка вместо LLM)

- Стенд детерминированный: вместо `qwen3.5-122b` работает
  `stub_upstream.py`, который отвечает по маркеру `[[stub:…]]`. Поэтому
  живые атаки в кадре воспроизводимы один в один, а пауз на «размышление
  модели» нет: ответ приходит за доли секунды.
- Заранее, вне кадра: `docker compose build`, первичный
  `./run-battle.ps1` (проверить, что всё зелёное), `docker compose down -v`
  для чистого старта, затем прогрев `docker compose up -d stub gateway`
  и один тестовый `curl` — чтобы образы и volume уже были готовы.
- Живых действий в кадре — три: `curl`-контроль, `curl`-атака, `GET /audit`.
  Полные прогоны (`tests`, `probes`, `attacker`, `loop`) можно снимать
  живьём: каждый занимает секунды, кроме `tests` — около минуты.
- Если позже переснимете с реальной моделью, ставьте маркер
  `[ПОКА МОДЕЛЬ ДУМАЕТ ~N с — филлер:]` и филлер на фактическое ожидание:
  числа из `bench/*.json` этого стенда к живой модели не относятся.
- Честная рамка обязательна в кадре: пробит **guard/loop**, а не «мозг
  нейросети». Не говорить «взломали qwen».

## Открыть до записи

### Чем запускать

| Инструмент | Зачем | Обязателен |
|---|---|---|
| Windows 10/11 | хост, на котором всё идёт | да |
| PowerShell 5.1 (встроен) или PowerShell 7 | все команды ниже; не WSL и не Git Bash | да |
| Docker Desktop, Linux-контейнеры (WSL2-бэкенд) | сам стенд: `docker compose` | да |
| Windows Terminal | удобные широкие таблицы и кириллица | желателен |
| VS Code или Notepad | открыть артефакты в `results/` (UTF-8) | да |
| Python 3.13 | **внутри образа**, на хосте не нужен | нет |
| Node.js / pnpm | к этому стенду отношения не имеют | нет |
| git | только чтобы посмотреть `git status`; прогон не требует | нет |

Проверка перед записью (каждая команда — одной строкой):

```
docker --version; docker compose version; docker info --format '{{.OSType}}'
```

В последней строке должно быть `linux`. Если `windows` — переключите Docker
Desktop на Linux-контейнеры (`Switch to Linux containers`).

Ubuntu в WSL **не нужна**: команды идут в PowerShell, а Linux даёт
Docker Desktop сам. WSL нужен только как внутренний бэкенд Docker Desktop,
заходить в него не надо.

### Ф10 · 08:10–08:50 · Д15-итог

Экран: `docker compose down`; затем `partner-attack-methodology.md`,
раздел 5 «Почему это сработало».

Текст:

> Почему это сработало. Входной guard ищет только секреты и
> персональные данные — инструкции он не проверяет. Клиентский system
> вливается в системный промпт шлюза, то есть инъекция попадает на
> верхний уровень доверия. Нормализация неполная: невидимые символы и
> похожие дефисы не приводятся к канону, а джойн, f-string и chr не
> декодируются. Выходной guard переиспользует входной, поэтому все дыры
> наследует. URL проверяется регуляркой на четыре числа через точку, а не
> разбором адреса. Команды — литеральные шаблоны без канонизации. Loop
> доверяет ревьюеру и не имеет детерминированного backstop. Ограничение
> честное: модель заменена заглушкой, поэтому это проверка guard'ов, а не
> проверка того, согласится ли реальная модель. С живой моделью те же
> payload'ы надо прогнать отдельно. Стенд гашу.
