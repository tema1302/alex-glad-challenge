# Blog Studio: блоги и промпты агентов

Веб-хаб `/blog/settings` и Android-раздел «Блоги» управляют всеми блогами и
промптами LLM-агентов. Доменная логика — в `challenge/src/core`, HTTP-контракт —
в `web/app/api/blogs/**`.

## Что можно сделать

1. Создать блог: имя, slug, профиль голоса, Telegram chat_id, пресет стиля.
2. Настроить блог: профиль, TG-канал, RSS-источники, контекст, пресет.
3. Архивировать/вернуть блог. Архив скрывает блог из селекторов, останавливает
   автоматизацию и расписание; посты/новости/стиль сохраняются.
4. Переопределить промпт любого из агентов и сбросить его к встроенному.
5. Видеть готовность: «готов к news» = есть профиль голоса и хотя бы один RSS.

## Агенты

| id | Что делает | Где применяется |
|---|---|---|
| `post.writer` | автор поста по новости | news-пайплайн, автоматизация |
| `post.topic` | автор поста по теме | ручной пост, расписание |
| `scout.news` | отбор новостей | news-пайплайн |
| `scout.orchestrator` | топ тем из источников | `/blog/scout` |
| `factcheck.reasoning` | пошаговая проверка фактов | news-пайплайн |
| `factcheck.verdict` | JSON-вердикт фактчекера | news-пайплайн |
| `digest.weekly` | недельный дайджест | `/blog/digest` |

`post.reviser` в реестр не входит: web-автоматизация его не вызывает, а REPL/FSM
работает без выбранного блога, поэтому per-blog override там не имел бы смысла.

### Порядок разрешения промпта

1. Переопределение блога (`blog_agent_prompts`).
2. `blogs.system_prompt` — только для `post.writer` и `post.topic` (легаси).
3. Пресет стиля (`style_preset`).
4. Встроенный default агента.

`post.writer` хранится в `blogs.system_prompt`: так его видят старые клиенты,
Telegram-команды и Android. Остальные агенты — в таблице `blog_agent_prompts`.
Явный сброс `post.topic` пишет пустой tombstone: он перекрывает
`blogs.system_prompt`, чтобы «Сбросить» действительно возвращал встроенный
промпт, а не тот же текст автора.

### Что не редактируется

JSON-схемы, severity-правила фактчекера, grounding-правила дайджеста, список
новостей/тем и лимиты остаются в коде. Переопределение меняет только смысловую
часть (роль, стиль, критерии), а код добавляет данные и машинный контракт.

В override можно использовать `{{channel}}`, `{{topic}}`, `{{style}}`,
`{{language}}`, `{{length}}`, `{{format}}`, `{{emoji}}`, `{{taboos}}`,
`{{signature}}`, `{{topK}}` и `{{priority}}` — они подставляются из профиля и
контекста блога. Неизвестные плейсхолдеры остаются как есть.

## HTTP API

| Метод/путь | Назначение |
|---|---|
| `GET /api/blogs` | активные блоги; `?includeArchived=1` — все |
| `POST /api/blogs` | создать блог (409 на дубль slug) |
| `GET /api/blogs/[slug]` | карточка блога |
| `PATCH /api/blogs/[slug]` | настройки, `status: active\|archived` |
| `GET /api/blogs/[slug]/agent-prompts` | реестр агентов и текущие override |
| `PUT /api/blogs/[slug]/agent-prompts` | `{agent, prompt: string\|null}` |
| `GET /api/blog/pulse` | сводка для dashboard |

Все мутации закрыты `requireApiAuth` (cookie или mobile Bearer). Ответы PATCH и
POST — camelCase `BlogDto`; `sources` всегда массив, `counts` — статистика,
`readyForNews` — готовность.

## UI

### Сайт

- `/blog/settings` — хаб: сводка, карточки, создание, архив.
- `/blog/settings/[slug]` — вкладки «Обзор / Пост / Промпты / Настройки / Расписание».
- «Пост» — ручной пост по теме (1–3 варианта, публикация первого варианта).
- Промпты: рейл агентов на desktop, select-подобный список на mobile, счётчик
  8000, предпросмотр, сброс к встроенному, защита от потери правок.
- Dashboard: блок «Пульс контента» (до 4 блогов, готовность, посты за 7 дней).

### Android

- «Блоги» — хаб со сводкой, готовностью и созданием; архивные блоги видны и
  возвращаются из карточки.
- Внутри блога: «Промпты агентов» (все 7), «Настройки» (общие поля + архив).
- PATCH отправляет только изменённые ключи; `prompt: null` уходит явным JSON null.

## Ограничения и риски

- Жёсткого удаления нет: только архив. Это защищает посты/новости/расписание от
  осиротевших строк.
- Override может ухудшить качество, но не ломает парсинг: JSON-контракты
  остаются в коде, фактчекер fail-closed.
- Промпты — доверенная админ-конфигурация; внешний контент в них не
  подставляется. Лимит 8000 символов на агента.
- Публичный `/blog/pipeline` не входит в этот контур и не получает блог-контекст.
