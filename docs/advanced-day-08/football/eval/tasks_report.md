# Три типа задач: где тюн, где промпт (day-08 football)

| Тип задачи | base-none | base-prompt (промпт) | tuned (тюн) | Вывод |
|---|---|---|---|---|
| Формат (day-07 full_match, 30) | 0/30 | 0.00 (тот же рантайм) / 0.13 (base-рантайм) | **0.37** | тюн > промпт |
| Факты (exact, 72+36) | 0.00 (нет контекста) | 0.17 (факты в промпте) | 0.69 (обучена на фактах) | тюн запоминает, но перенос на парафразы нестабилен |
| Стиль-тон (rule-score, 12) | 0.25 | 0.42 | 0.33 | тюн на JSON не переносится |

## Чтение цифр

- **Формат**: тюн выигрывает у промпта в одном рантайме (0.37 vs 0.00) и не требует few-shot в проде.
- **Факты**: без контекста фактов нет ни у кого; у 0.5B на ЧИСЛОВЫХ фактах тюн (0.69 суммарно) обгоняет чтение промпта (0.17), но перенос на переформулировки всего 39% — запоминается связка вопрос→ответ. Для стабильных справок тюн оправдан; для часто меняющихся фактов — промпт/RAG (у крупных моделей чтение надёжнее, см. старый day-08).
- **Стиль**: промпт помогает нестабильно; тюн парсера на стиль не переносится (иногда мешает).
