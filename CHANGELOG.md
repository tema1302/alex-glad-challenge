## День 10 — Управление контекстом: разные стратегии (без summary)
**Дата:** 2026-06-14

**Задание (полный текст):**
> 3 стратегии управления контекстом (минимум) + переключатель:
>
> Стратегия 1: Sliding Window
> - только последние N сообщений
> - остальное отбрасывать
>
> Стратегия 2: Sticky Facts / Key-Value Memory
> - блок "facts" (ключ-значение) — важные данные из диалога (цель, ограничения, предпочтения, решения, договорённости)
> - обновлять facts после каждого сообщения пользователя
> - в запрос: facts + последние N сообщений
>
> Стратегия 3: Branching (ветки диалога)
> - checkpoint в диалоге
> - 2 ветки от одного места
> - продолжить диалог в каждой ветке независимо
> - переключаться между ветками
>
> Тест на одном сценарии (например "собираем ТЗ 10–15 сообщений"): прогнать каждую стратегию, сравнить ответы и поведение.
>
> Сравнить: качество ответа, стабильность (не теряет ли детали), расход токенов, удобство.
>
> Результат: агент с 3 стратегиями (Sliding Window / Facts / Branching) + сравнение.
> Формат: видео + код.

**Сделано:**
- Три класса реализуют `ContextStrategy` из `@challenge/core`.
- Демо: один сценарий (сбор ТЗ) на каждой стратегии.
- Branching: `checkpoint(label)` + `switchTo(id)`.

**Выводы:**
- Sliding — самый дешёвый, но теряет факты.
- Sticky Facts — лучший баланс при адекватных правилах извлечения.
- Branching незаменим для "что если" и A/B тестинга промптов.

**Код:** `challenge/src/demos/day-10.ts`

## Feature: блог-агенты для канала «Иди на факты глянь»
**Дата:** 2026-06-17
**Ветка:** `feature/blog-agents`

**Цель:** автоматизировать ежедневную подготовку постов для футбольного Telegram-канала. Три агента в pipeline: сбор новостей → написание поста в авторском стиле → фактчекинг.

**Что сделано:**
- Хранилище: SQLite через `node:sqlite` (Node 24+, без нативных сборок). Таблицы `news`, `posts`, `style_samples` с UNIQUE-индексами против дублей.
- RSS-загрузчик: sports.ru, championat.com, BBC Sport (через `fast-xml-parser`).
- Агент 1 (NewsFetcher): LLM-выбор top-K хайповых из неиспользованных.
- Агент 2 (PostWriter): few-shot на 5 случайных образцах стиля канала.
- Агент 3 (FactChecker): JSON-verdict, сверка фактов с источником.
- CLI: `news`, `seed-style`, `db-stats` с флагами `--hours`, `--top`, `--for`.
- Документация: раздел про хранение контекста, cron для Windows/Linux.

**Параметры:**
- Провайдер: DeepSeek (через `.env`).
- Источник стиля: 13 реальных постов канала (через `seed-style`).
- Хранилище: `challenge/.data/blog.sqlite` (в `.gitignore`).

**Smoke-результат** (реальный прогон):
- Агент 1: топ-3 (Роналду-ЧМ, Скалони-Месси, Англия-Хорватия).
- Агент 2: пост про Скалони, 219 символов, с шапкой/CAPS/иронией/подписью.
- Агент 3: `verdict: ok`, «Пост полностью соответствует источнику».

**Выводы:**
- `node:sqlite` годится для локальных cron-агентов без боли с нативными сборками (`better-sqlite3` требует ClangCL toolchain на Windows).
- Строгий JSON-промпт требует: явный пример, требование «первый символ ответа — `[`», `maxTokens >= 2000` для больших промптов, толерантный парсер (устойчив к markdown-обёртке и обрыву).
- Few-shot на 5 случайных образцов стиля даёт удовлетворительный результат; для проде расширить до 10-15 и/или кластеризовать по типам постов.

**Код:**
- `challenge/src/core/db.ts` — слой SQLite.
- `challenge/src/core/agents/{rss,newsFetcher,postWriter,factChecker,pipeline,seed}.ts`
- `challenge/src/data/style-samples.json` — 13 образцов стиля.
- Команды в `challenge/src/cli.ts`: `news`, `seed-style`, `db-stats`.

## День 16 — MCP-клиент: соединение и список инструментов
**Дата:** 2026-06-24

**Задание (полный текст):**
> В рамках шестнадцатого дня необходимо написать код общения с МСП Claude In
> Mobile. Сделайте минимальный код, который:
> - устанавливает MCP-соединение
> - получает от MCP список доступных инструментов

**Сделано:**
- `core/mcp.ts` — минимальный MCP-клиент: JSON-RPC 2.0 поверх stdio дочернего
  процесса. Проводит handshake (`initialize` → `notifications/initialized`),
  затем вызывает `tools/list` (и умеет `tools/call`).
- `demos/day-16.ts` — сценарий: запускает `claude-in-mobile`, печатает
  `serverInfo` и список инструментов.

**Выводы:**
- MCP — это JSON-RPC 2.0. Транспорт stdio: клиент пишет запросы в stdin
  дочернего процесса, читает ответы из stdout, по одной строке на сообщение.
- Жизненный цикл строго трёхфазный: `initialize` (обмен версиями протокола и
  capabilities) → `notifications/initialized` (клиент готов) → обычные запросы.
  Без `initialize` сервер не отвечает на `tools/list`.
- Версия протокола согласуется в `initialize`: клиент шлёт `2025-06-18`, сервер
  подтверждает ту же. Несовпадение — повод разорвать соединение.
- claude-in-mobile v3.14.0 (profile `core`) отдаёт 14 инструментов: 7
  мета-инструментов (`device`, `screen`, `input`, `ui`, `app`, `system`,
  `flow`) + 7 REPL-инструментов (`repl_spawn`, `repl_send`, `repl_key`,
  `repl_expect`, `repl_snapshot`, `repl_list`, `repl_kill`). Опциональные
  модули (`browser`, `desktop`, `store`) подгружаются через
  `device(enable_module)`.

**Smoke-результат** (реальный прогон):
```
protocol: 2025-06-18
server:   claude-in-mobile v3.14.0
Инструментов доступно: 14
```

**Код:**
- `challenge/src/core/mcp.ts` — `McpStdioClient`: connect/handshake/listTools/callTool/disconnect.
- `challenge/src/demos/day-16.ts` — демо: запуск сервера + печать инструментов.
