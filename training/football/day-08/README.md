# Day 8 (футбольный трек) — границы файнтюнинга

День измерений на тех же весах, что day-07 (Qwen2.5-0.5B-Instruct + LoRA
парсера NL→JSON): что тюн чинит, что ломает и чем платит. Все прогоны
реальные: CPU fp32 transformers, temperature=0, seed=42.

## Пайплайн

```text
gen_facts.py -> train_facts.py                    (s1: факты в весах)
gen_outdomain.py -> eval_outdomain.py             (s2: потери вне домена)
sweep_checkpoints.py (адаптеры day-07)            (s3: переобучение)
gen_style.py -> eval_style.py -> tasks_report.py  (s4: три типа задач)
```

## s1 — факты: в контекст читаются, в веса лезут ненадёжно

36 ВЫМЫШЛЕННЫХ фактов про Челси/АПЛ (академия, трансферы, рекорды, U21 —
модель их знать не может), 72 вопроса (orig + para). Протокол как в старом
day-08: обучение 30 эпох на orig-формулировках (ассоциативное запоминание
требует десятков проходов), затем 4 режима.

| Режим | exact | n |
|---|---|---|
| trained-none-orig (обучающая формулировка) | 36/36 (100%) | 36 |
| trained-none-para (переформулировка) | 14/36 (39%) | 36 |
| base-none | 2/72 (3%) | 72 |
| base-prompt (факты в system) | 12/72 (17%, relaxed 16/72) | 72 |

Чтение результата (тоньше лозунга «факты не влезают в веса»):
- Веса запоминают обучающую формулировку идеально (36/36), но перенос на
  переформулировку всего 39% — модель помнит «связку вопрос→ответ», а не факт.
- Промпт у 0.5B на числовых фактах слаб (17% exact): суммы трансферов и
  рекорды («42», «47315», «94.7») модель теряет при чтении длинного system.
  У старого трека (текстовые факты, 1.5B/7B) чтение давало 50–69%.
- Практически: для числовых справок 0.5B — ни тюн (хрупкий перенос), ни
  промпт (слабое чтение); нужен RAG с точной выдачей или модель крупнее.
- Цена промпта по latency: base-prompt 4.9 с/запрос против ~0.9–1.0 с
  у обученной.

## s2 — цена тюна вне домена (24 кейса: chat/math/translate/code)

Нейтральный system prompt; base vs tuned (адаптер day-07). Скореры:
math — число совпало; translate — токен-F1 ≥ 0.8 к референсу; code —
извлечённый def исполняется, asserts проходят (песочница с безопасными
builtins); chat — не отказ и не футбольный поворот.

| Модель | avg | math | translate | code | chat |
|---|---|---|---|---|---|
| base | 0.583 | 0.167 | 0.833 | 0.333 | 1.0 |
| tuned | **0.667** | 0.167 | 0.833 | 0.667 | 1.0 |

Неожиданно: цены тюна НЕТ — tuned в среднем лучше base (+0.084), код
вырос с 0.333 до 0.667 (дисциплина структуры из JSON-тюна переносится
на `def`-ы), math/translate/chat не изменились. Отличие от старого
day-08 (−0.08): там база была сильнее (1.5B) и системный промпт с
todo-priming'ом; здесь нейтральный системный промпт и слабая база —
тюн дал дисциплину, не отняв общих способностей. Вывод привязан к связке
«узкий тюн + нейтральный промпт + слабая база».

## s3 — переобучение: свип эпох day-07

Чекпоинты adapter-epoch1/2/3 на valid day-07 (full_match) и out-of-domain
(avg). Ищем точку, где valid уже не растёт, а вне-доменное качество падает.

| Чекпоинт | valid full_match | out-of-domain avg |
|---|---|---|
| epoch1 | 11/42 (26%) | 0.708 |
| epoch2 | 12/42 (29%) | 0.708 |
| epoch3 | 25/42 (60%) | 0.667 |

Кривая train/val loss (day-07): 0.0496 → 0.0401 → 0.0338 — расхождения НЕТ,
переобучения по лоссу не видно. Даунстрим-картина тоньше: в-domain качество
скачком растёт на 3-й эпохе (11/12 → 25/42), а out-of-domain в это время
проседает на −0.04 (0.708 → 0.667). Классического «valid перестаёт падать»
нет, но цена вне домена появляется именно на эпохе 3. Практически:
эпоха 2 — сбалансированный выбор (29% valid при 0.708 ood), эпоха 3 —
максимум в-domain. Отличие от старого day-08 (там хватало 1–2 эпох):
наши valid-примеры ближе к train-распределению, и 3-я эпоха реально
добирает сложные случаи.

Плюс контроль «на запросах, непохожих на обучающие»: eval-30 (handcrafted,
harder) для эпохи 3 — 11/30 (37%) против 25/42 (60%) на template-valid:
разница распределений, а не противоречие.

## s4 — три типа задач (формат / факты / стиль)

Единый отчёт `tasks_report.md`: формат = day-07 eval, факты = s1, стиль =
12 футбольных кейсов с rule-проверками (романо-твит «Here we go», BBC без
«!», лимиты длины, обязательные слова). Режимы: base-none, base-prompt,
tuned.

| Тип задачи | base-none | base-prompt | tuned | Вывод |
|---|---|---|---|---|
| Формат (full_match, 30) | 0/30 | 0/30 zero-shot в же рантайме (4/30 с few-shot) | **11/30** | тюн > промпт |
| Факты (exact) | 2/72 | 12/72 | 50/72 (orig 36/36, para 14/36) | тюн запоминает, перенос нестабилен |
| Стиль (rule, 12) | 0.25 | 0.42 | 0.33 | промпт помогает; JSON-тюн не переносится |

## Итог дня: когда что использовать

1. **Формат и повторяющиеся паттерны → тюн.** 0.37 против 0.00 zero-shot
   и 0.13 у few-shot; few-shot в проде не нужен.
2. **Факты → зависит от типа фактов и модели.** У 0.5B на числовых фактах
   тюн (0.69) сильно обгоняет промпт (0.17), но перенос на парафразы 39%.
   Стабильные справки — можно тюнить; часто меняющиеся — промпт/RAG.
3. **Стиль-тон → промпт (с проверкой).** 0.42 у промпта, 0.33 у тюна;
   тюн парсера на стиль не переносится.
4. **Переобучения по лоссу нет**, но цена вне домена появляется с 3-й
   эпохи (−0.04 ood) — баланс выбирать по downstream, не по лоссу.
5. **Цена тюна вне домена при нейтральном системном промпте отсутствует**
   (0.667 vs 0.583) — отличие от старого day-08 с todo-priming'ом.
