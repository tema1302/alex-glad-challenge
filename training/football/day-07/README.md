# Day 7 (футбольный трек) — свой датасет: NL → JSON матча (АПЛ/Челси)

Узкая повторяющаяся задача с проверяемым результатом: русскоязычная заметка
о футбольном матче → строгий JSON. Та же модель и рантайм, что в day-06
(Qwen2.5-0.5B-Instruct, CPU fp32) — сравнение честное, одна переменная.

## Задача и «верный ответ»

```json
{"home":"Челси","away":"Арсенал","home_score":2,"away_score":1,
 "scorers":[{"team":"Челси","player":"Мудрик","minute":34}, ...],
 "competition":"АПЛ","venue":"Стэмфорд Бридж"}
```

Верный ответ = точное совпадение всего JSON после каноникализации (сортировка
бомбардиров по минуте). Соглашения (в system prompt, см. `prompts.py`):
счёт всегда «дом:гости»; не назван стадион → домашний стадион принимающего;
«дома»/«на выезде» различаются; превью без счёта → null/null/[].

## Данные (в git: `data/`, `eval/`)

| Набор | Размер | Источник |
|---|---|---|
| train | 318 | шаблонный движок поверх `seeds.py` (20 клубов АПЛ, стадионы, 56 игроков, ~40 паттернов фраз), gold по построению |
| valid | 42 | hash-сплит (seed 42) |
| eval | 30 | ручная разметка `gen_eval.py` (игроки только из PLAYERS_EVAL, с train не пересекаются) |

Чистка/контроль (`check_split.py`, всё зелёно): точные дубли текста — 0;
пересечений текста eval/train — 0; пересечения игроков train/eval — 0;
баланс: АПЛ 249 / Кубок Англии 37 / ЛЧ 32; результатов 260 vs превью 58;
побед дома 106 / в гостях 108 / ничьих 90 (проверено до правок паттернов,
итоговые числа — в выводе скрипта).
Глазное ревью 30 случайных (`sample_review.py`, 2 итерации): найдены и
исправлены падежные ошибки («в матче Лиге чемпионов» → «Лиги чемпионов»),
склонение клубов («у «Арсенала»»), дубль клуба в голевой clauses,
«хет-трик» при 4 голах («покер»), превью без турнира (неверифицируемое поле).

## Методология

- Одинаковые tokenizer/chat-template; temperature=0 (do_sample=False),
  seed=42; max_new_tokens=220.
- Метрики: parse_ok (JSON парсится), format_ok (ровно один JSON без прозы),
  full_match (все поля), per-field accuracy (home/away/scores/scorers/
  competition/venue), latency.
- base-prompt и tuned — одна загрузка модели, разница ровно адаптер
  (`disable_adapter()`); baseline из другого режима того же скрипта.

## Риски

- 318 примеров — нижняя граница; фокус на качестве разметки, не объёме.
- Имена игроков/клубов — разметочные метки парсера, не фактические составы.
