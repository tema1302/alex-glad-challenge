# Видео-скрипт: Day 7 (футбольный трек) — свой датасет: NL → JSON матча

Хронометраж ~7–9 минут. Цифры — из `docs/advanced-day-07/football/eval/`.

## 1. Задача (0:00–1:30)
- Показать спеку: русская заметка о матче → строгий JSON (home/away/счёт/
  бомбардиры с минутами/турнир/стадион). Верный ответ = точное совпадение.
- Конвенции (счёт от домашней, стадион по умолчанию, превью → null) —
  в system prompt, показать `prompts.py`.
- Почему АПЛ/Челси: 20 клубов, стадионы, Челси в трети eval-кейсов.

## 2. Датасет (1:30–3:30)
- seeds.py: клубы/стадионы/игроки; generate_data.py — шаблонный движок,
  gold по построению. 318 train / 42 valid / 30 eval (ручная разметка).
- Чистка (check_split.py): дубли 0, пересечений 0, игроки train/eval
  не пересекаются, баланс классов.
- Глазное ревью 30 примеров — найденные баги вербализатора (падежи,
  «хет-трик» при 4 голах, превью без турнира) и их исправление.

## 3. Baseline без тюна (3:30–4:30)
- Результаты: none 0/30 (parse 0 — рассуждает вместо JSON);
  prompt (system + 3 few-shot) — full_match 4/30, venue 14/30,
  бомбардиры 12/30. Это планка.

## 4. Обучение (4:30–5:30)
- Qwen2.5-0.5B + LoRA r=16, system prompt, 3 эпохи, CPU fp32.
- Кривая loss (loss.svg). Инфраструктурная находка: логиты fp32 на
  длинных JSON >1 ГБ — batch 4 × accum 2, иначе segfault; вал-батч 4.

## 5. Tuned vs base-prompt (5:30–7:30)
- Одна загрузка, адаптер вкл/выкл. Таблица full_match tuned vs base-prompt.
- Разбор регрессий (из tuned_report.md): где tuned ошибается.
- Вывод дня: тюн против 4/30 промпта — цифры из tuned.json.

## 6. Итог (7:30–8:00)
- Свой датасет 318 примеров обучен; промптинг превзойден / не превзойден —
