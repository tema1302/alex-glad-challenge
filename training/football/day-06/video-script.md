# Видео-скрипт: Day 6 (футбольный трек) — первый тюн на готовом датасете

Хронометраж ~6–8 минут. Записывать поверх реального прогона
(`training/football/day-06`), все цифры — из `artifacts/run.json` и
`docs/advanced-day-06/football/eval/`.

## 1. Задача и выбор датасета (0:00–1:30)
- Слайд: HF `shehrozrafaqat/global-football-assistant-dataset` — 9600
  ChatML-примеров из 302 фактов. Показать `football_chatml_all.jsonl`,
  DATA_CARD.md.
- Почему он: узкая роль (футбольный ассистент), жёсткий стиль ответов,
  заметное поведенческое изменение — плюс дисциплина date-aware safety.
- Оговорка: лицензия на карточке не указана — для демо, не для прод.

## 2. Модель и железо (1:30–2:30)
- Машина без CUDA (AMD RX 7600) → обучение на CPU: fp32 LoRA (peft),
  12 потоков, Qwen2.5-0.5B-Instruct (в кэше HF).
- Сравнить с Kaggle T4 (прошлый трек day-06 SQL) — там был QLoRA 1.5B.

## 3. Данные: честный сплит (2:30–3:30)
- Ловушка: 9600 примеров = 302 факта → случайный сплит протекает.
  Показать prepare_data.py: групповой сплит по fact_id.
- eval-20: 10 in-domain (Chelsea включён), 5 edge (date-aware), 5 ood.

## 4. Обучение (3:30–5:00)
- Запуск train_lora.py; скрин step log; loss 3.49 → 0.017.
- 41 минута, 2446 с; val loss 0.70 → 0.69 (почему высокий: вал-факты
  модель не знает — учим стиль/роль, не знания).
- loss.svg на экране.

## 5. До/после на 20 запросах (5:00–7:00)
- Таблица: in-domain F1 0.10 → 0.53; exact 0 → 1; edge 1/5 → 1/5;
  ood 5/5 → 5/5; latency 24.7 с → 8.9 с.
- Показать 2–3 сырых ответа из results.jsonl (base мямлит, tuned в стиле
  «For this dataset, verified on 2026-04-23 …»).
- Регрессия d6-edge-12: adversarial-формулировка → tuned даёт определение
  вместо осторожного ответа. Честно: на чём тюн стал хуже.
- ISO-дата в преамбуле → ложное срабатывание скорера: как чинили.
