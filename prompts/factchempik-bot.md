# ПРОМПТ: Telegram-бот «Фактчемпик» — память и шаржист чата «Факты в чате»

> Самодостаточный промпт для кодинг-агента. Скармливать целиком.
> Продукт: бот ВНУТРИ приватного Telegram-чата «Факты в чате» (дискуссионный
> чат канала «Иди на факты глянь», t.me/lookAtFactsChat), который по командам
> участников достаёт из истории чата реальные цитаты конкретного человека и
> (позже) воображает его реакции. Исследовательская база: `swarm-report/
> factchempik-research-{data,infra,product}-01.md` + план решений
> `swarm-report/factchempik-plan-01.md` (читать первыми). Язык всего — русский.

## 0. Роль и рамка

Ты — фича-разработчик репозитория `alex-glad-challenge` (pnpm-монорепо:
`challenge/` — Node 24 + TypeScript strict ESM, запуск через tsx без сборки;
`web/` — Next.js, в этой задаче не трогается). Режим — фичеризм (CLAUDE.md §1.1):
ветка `feat/factchempik-bot` от `main`, squash-merge, точка входа — новая
CLI-команда, `src/demos/registry.ts` НЕ трогается. Новые npm-зависимости
запрещены (Bot API — сырой fetch через `netFetch`, БД — `node:sqlite`).

Железная продуктовая граница (нарушение = брак):
- **Реальные цитаты** — только из БД, атрибуция по `from_id` проверяется
  КОДОМ (не LLM), в выводе всегда дата сообщения.
- **Воображаемое** («как бы сказал») — только через 🎭-маркер первой строкой,
  который проверяет код (порт паттерна `web/lib/shared/joker-marker.ts` +
  гейт-логика `web/lib/server/joke-guard.ts`: буфер, 1 ретрай, fallback).
  Без валидного маркера сообщение не отправляется.

## 1. Зафиксированные факты (проверены Research, НЕ галлюцинировать)

- БД: `challenge/.data/tg.sqlite`, таблица `tg_messages`:
  `chat_id, topic_id, msg_id, from_id (ключ автора; NULL — 381 шт., игнорировать),
  from_name (у 99% авторов один вариант), text ('' — media-only),
  date_iso, reactions_json, reaction_total`; PK (chat_id, topic_id, msg_id).
  Доступ — через `TgStore` (`challenge/src/core/tg/tgStore.ts`); для новых
  запросов добавляй АДДИТИВНЫЕ методы в TgStore или отдельный store
  (`core/tg/botStore.ts`), сырой SQL не размазывать.
- Чат: `chat_key='-1001736860345'`, topic_id=0, 949 747 сообщений,
  2021-12-28 → 2026-09-19; 865 957 с текстом; 2 170 авторов с текстом;
  топ-100 авторов покрывают 96,7% текста; 1 237 авторов имеют 1–5 сообщений.
- Персонажи-примеры владельца (найдены, ники ЛАТИНИЦЕЙ — кириллические
  запросы дают 0 совпадений): Saveliy (from_id 662123302, 146 327 сообщ.,
  автор №1), Sevens ABSOLute (587493810, 56 795), krasnobeliy2 Вячеслав
  (1321375335, 47 838).
- Бот-канал «Иди на факты глянь» (from_id `-1001298193122`) — НЕ участник:
  исключать из цитат/игр/профилей (константа в коде).
- Реакции в чате: ≥1 у 106 339 сообщ., ≥3 у 21 432, ≥5 у 12 119 — пул
  «цитатника» с порогом ≥3 (~20k), выборка уже поддержана индексом
  `idx_tg_top` (reaction_total DESC).
- RAG (`rag.sqlite`, strategy='telegram') для этой фичи НЕ используется:
  чанки склеивают сообщения разных авторов, per-author retrieval невозможен
  (подтверждено сэмплами). Свой путь — FTS5.
- FTS5 доступен в node:sqlite (SQLite 3.53.0). Полный индекс по чату:
  ~9 с сборки, ~141 МБ, запросы 0.3–4.7 мс, морфология — префиксом
  (`факт*` матчит факт/факты/фактов), `snippet()` работает.
- Telegram: `TG_BOT_TOKEN` уже в .env; в репо бот-инфраструктура = только
  публикация (`core/agents/telegram.ts` publishPost, HTML parse_mode,
  netFetch, label 'Telegram Bot API'). `getUpdates` нигде нет — пишешь с нуля.
  Сеть: ВСЕ вызовы api.telegram.org — через `netFetch` (`core/net.ts`,
  chokepoint-инвариант репо). Long polling: `getUpdates?timeout=25` +
  `timeoutMs: 35_000`. gramjs/MTProto боту не нужен.
- Env-инвариант: process.env читается только в `core/env.ts` — добавь туда
  accessor `getTgBotRuntimeConfig()` и блок в `.env.example`:
  `TG_BOT_ALLOW_CHATS` (CSV chat_id, дефолт пусто = бот НЕ работает —
  fail-closed). `TG_CHAT_ID` (канал публикации) НЕ переиспользовать.
- Профили авторов (`tg_profiles`) ЕЩЁ НЕ СУЩЕСТВУЮТ: джоба описана в
  `prompts/lookatfacts-profiles.md` и выполняется ОТДЕЛЬНО. Не блокируй M1
  профилями; `/профиль` и `/какбы` — за зависимостью (мильстоуны ниже).

## 2. Архитектура

- Точка входа: CLI-команда **`tg-bot`** в `challenge/src/cli.ts`
  (паттерн `tg-collect`: разбор флагов, check config, подключение, SIGINT).
  Логика — в `challenge/src/core/tg/bot.ts` (+ `botStore.ts` при нужде),
  клиент Bot API — `core/agents/telegram.ts` или рядом (апи-хелпер
  `botApi(method, payload)` через netFetch; токен в URL НЕ логировать).
- Цикл: `deleteWebhook` при старте → `getUpdates(offset, allowed_updates=
  ["message","callback_query"])` → фильтр allow-list → ПОСЛЕДОВАТЕЛЬНЫЙ
  handler → исходящая очередь (≥1.2 с между сообщениями чата; 429 →
  sleep(retry_after+1); ответ >4096 знаков → пагинация кусками ≤3900).
- Состояние: таблица `tg_bot_state(key TEXT PK, value TEXT)` в tg.sqlite
  (offset; in-memory dedup по update_id). SIGINT/SIGTERM: drain очереди →
  persist offset → close → exit 0. Сетевые сбои → backoff ×2 (макс 5),
  не exit. Telegram 409 Conflict (второй инстанс) → exit(1) с внятным логом.
- FTS5-индекс: отдельный файл `challenge/.data/tg-fts.sqlite`
  (`fts5(text, from_id UNINDEXED, msg_id UNINDEXED, date_iso UNINDEXED)`;
  инкремент по `msg_id > max_indexed`; полная перестройка ~9 с).
  Управление: автоматическая доклейка новых сообщений при старте бота +
  админ-команда `/reindex`.
- Конфиг бота в рантайме: `getTgBotRuntimeConfig()` → { token, allowChats:
  Set<string>, ownerChatId } ; owner = первый chat_id из allow-list ИЛИ
  отдельная переменная `TG_BOT_OWNER_ID` (реши по простоте, задокументируй).

## 3. Имя → автор (дизамбигуация) — ядро UX

1. Нормализация входа: trim, lower, `ё→е`.
2. Словарь алиасов (таблица `tg_bot_aliases(alias TEXT PK, from_id TEXT)`,
   в tg.sqlite) с SEED при первой инициализации: `савелий→662123302`,
   `sevens`/`севенс→587493810`, `краснобелый`/`вячеслав→1321375335`
   (проверь by фактическим lookup — это seed, админ расширит).
3. Резолв: алиас точный → автор; иначе подстрока по DISTINCT
   (from_name, from_id) с нормализацией; результатов 0 → отказ с 3
   ближайшими подсказками; 1 → молча используем; >1 → inline-кнопки
   `«Saveliy · 146 327 сообщ. · 2022–2026»` (callback_data `res:<msgctx>:<id>`,
   `answerCallbackQuery` обязателен), выбор живёт 60 с.
4. Человекочитаемое имя автора в ответах — текущий from_name; from_id
   НИКОГДА не показывается.

## 4. Мильстоуны и команды

### M1 — бот без LLM (ядро ценности)
- **`/цитата [имя]`**: без имени — случайная из топа чата (reaction_total≥3,
  исключая бот-канал); с именем — случайный топ цитат автора. Вывод:
  «[12.03.2024] <display_name>:» + текст (≤600 зн., многоточие при обрезке).
- **`/сказал <имя> [тема…]`**: FTS5 `MATCH` (тема → OR-набор токенов с
  префиксным октрюхом `корень*`; стоп-слора — готовый STOP_WORDS из
  `core/agents/telegramScan.ts`) + `from_id`; буст: reaction_total и
  свежесть; вывод: 3–5 цитат, КАЖДАЯ с датой; если тема пуста и это
  REPLY на сообщение чата — темой становятся 3–5 значимых слов реплики,
  на которую отвечают. Атрибуция уже гарантирована SQL.
- **`/игра`**: «кто это сказал» — реальная цитата (reaction_total≥5,
  40–400 зн.), 4 inline-кнопки (1 верный + 3 дистрактора из топ-авторов),
  90 с на раунд, ведение счёта сессии в памяти, финал — топ мини-табличка.
  Один активный раунд на чат.
- **Админ (только ownerChatId)**: `/reindex` (полный FTS-реbuild),
  `/алиас <ник> <имя-автора>` (добавить в словарь), `/off` (бот перестаёт
  отвечать до `/on`), `/стат` (авторизованных апдейтов, очередь, размер
  FTS, последний idx msg_id).
- Инвокации: команды; reply на сообщение бота + `@фактчемпик …` в тексте.
  Privacy mode бота — ВКЛ (этого достаточно), отключение не требуется.

### M2 — профили (зависимость вне этого промпта)
Джоба `tg-profile build` (отдельный промпт) наполняет `tg_profiles`.
Бот: `/профиль <имя>` — `portrait_short` + 3–4 факта + активность;
если профиля нет — честно «профиль ещё не построен» (не выдумывать).

### M3 — `/какбы <имя> [тема|reply]`
Вход: профиль + 8–10 выдержек автора (few-shot) + контекст темы; LLM —
локальная Ollama по умолчанию (cloud — только если локальная не настроена),
temperature ~0.9, maxTokens ~300. Ответ ВСЕГДА: строка 1 —
`🎭 Это воображаемая реплика в манере <display_name>, не настоящая`;
далее — сама реплика (≤500 зн.). Код-гейт: нет 🎭-маркера → 1 ретрай →
fallback-текст с маркером. Запросы на «оскорби/угрозы/личную жизнь/
политику» → вежливый отказ (без генерации). LLM недоступен → ответ с
валидным маркером «стилизатор остыл, попробуй позже» (не сырой стектрейс).

## 5. Guardrails (STRICT)

1. Allow-list чатов: отвечать ТОЛЬКО в чатах из `TG_BOT_ALLOW_CHATS`
   (стартовое значение: `-1001736860345`) и в личке owner; всё прочее —
   молча игнорировать.
2. Кулдаун per-user: 3 команды/мин (soft — при превышении короткая
   подсказка раз в 30 с), глобальная очередь отправки ≥1.2 с.
3. Реальная цитата без даты в выводе = баг; воображаемое без 🎭 = баг
   (оба кейса покрыть тестами).
4. Ничего из БД (цитаты, профили, from_id) не отправляется никуда, кроме
   разрешённых чатов; логи — без текстов сообщений (только метаданные).
5. Деликатность: /какбы стилизует МАНЕРУ (лексика/ритм), не приписывает
   автору факты, мнения о реальных людях, личную жизнь; запросы «пусть X
   оскорбит Y» → отказ.
6. Ошибки LLM/БД не должны молча глотаться: деградация с человекочитаемым
   ответом; ретраи ×2 макс.

## 6. Тесты и приёмка

- vitest-подобные юнит-тесты (в `challenge/` — `node --test` или vitest
  по конвенции репо; посмотри, как тестируются core-модули) на:
  нормализацию/резолв имён (включая seed-алиасы), парсер команд,
  сборку FTS-запроса (префиксная морфология, стоп-слова), 🎭-гейт
  (валид/невалид/ретрай/fallback), очередь отправки и кулдауны,
  пагинацию 4096. Фикстуры — временная sqlite c 10–20 строками.
- `pnpm --filter challenge typecheck` — чисто (гейт перед коммитом).
- Ручной smoke-чеклист в PR: с реальным токеном в личке owner:
  /цитата, /сказал севенс парковка, /игра (раунд), неизвестное имя,
  неоднозначное имя (кнопки), /off и повторная команда, рестарт процесса
  (offset не теряет сообщения, дублей нет).
- README/CHANGELOG: запись фичи (что это, как запустить, env-переменные,
  команды), обнови `.env.example`.

## 7. Не делать

- Не подключать telegraf/grammY/ др. фреймворки и любые новые зависимости.
- Не читать все сообщения группы (privacy OFF) и не реализовывать
  «голые» фразы без команды — это отдельное решение владельца (v1.1).
- Не реконструировать «кому отвечали» (reply-данных в БД нет —
  восстановление = выдумка); reply-контекст берётся ТОЛЬКО нативно из
  Bot API в момент инвокации.
- Не трогать `rag.sqlite`, чаты EVOLUTE (`-1001508192874`) и Антонов
  (`-1001324711820`), не менять схемы существующих таблиц деструктивно.
- Не публиковать ничего в канал публикации (`TG_CHAT_ID`) из бота.
